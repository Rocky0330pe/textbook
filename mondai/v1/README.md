# 問題集 第1巻：わざの書き方（書く組への手引き）

決めたこと：第28回 M-1〜M-9（`docs/議事録/第28回編集委員会_議事録_数学問題集の方針.md`）。わざの番号と中身の一覧は `v1/CATALOG.md`。見本は `v1/a_tasu.js` の 1-02、`v1/c_kake.js` の 1-37・1-43。

## 1. ファイル

- わざは組ごとのファイルに書く：`a_tasu.js`（1-01〜1-13）、`b_hiku.js`（1-14〜1-25）、`c_kake.js`（1-33〜1-48）、`d_waru.js`（1-49〜1-56）、`e_hakaru.js`（1-26〜1-32）、`f_katachi.js`（1-57〜1-62）。
- ファイルの形は見本と同じ：`(function (M) { 'use strict'; M.add({...}); ... })(globalThis.MONDAI);`
- ほかの組のファイル・`core.js`・`build/*`・`tex/*`・`v1/parts.js` は書きかえない。要るものは報告に書く。
- ブラウザでもそのまま動くように、`require` や `import` は使わない。外のライブラリも使わない。

## 2. わざの形

```js
M.add({
  id: '1-37',            // CATALOG.md の番号（変えない）
  part: 3,               // 部の番号（CATALOG.md）
  chap: '1-13',          // 教科書の章
  stars: 1,              // 1 か 2（CATALOG.md）
  title: '…',            // CATALOG.md の名前
  mark: '…',             // 見分ける目印。1〜2行。強めたい所は **…**（太字と下線になる）
  futsu: ['…', '…'],     // ふつうに解くと（3行まで）
  raku: ['…', '…'],      // 楽な形にすると（4行まで。式は「＝」でつなぐ）
  why: '…',              // どうして楽になるの？（2行まで。教科書の章を指してよい）
  caution: '…',          // 使えないとき（2行まで）
  counts: { s1: 10, s2: 8, s3: 6, trap: 2 },   // 省略するとこの数。合計は 20〜30
  cols: 2,               // 問題の列の数（長い文の問題は 1）。ステップごとなら { s1: 2, s3: 1 }
  boxw: '15mm',          // 答えの欄のはば（単位つきの答えは広く。例 '22mm'）。ステップごとなら { s3: '22mm' }
  steps: {
    s1(r) { … return { q, a, easy }; },   // ステップ1 そのまま つかう
    s2(r) { … },                          // ステップ2 すこし かたちを かえる
    s3(r) { … },                          // ステップ3 見かけが ちがう
    trap(r) { … },                        // わなに ちゅうい（目印に似ているが楽にならない）
  },
});
```

- `r` は種つきの乱数：`r.int(lo, hi)`（lo以上hi以下）、`r.pick(配列)`、`r.chance(p)`、`r.shuffle(配列)`、`r.intNot(lo, hi, 除く条件)`。`Math.random` は使わない（同じ種で同じプリントにならなくなる）。
- 作れないときは `null` を返してよい（作り直す）。同じ問題（`q` が同じ）は1枚に2回出ない。各ステップで、決めた数の、ちがう問題が作れるようにする（`check.js` が確かめる）。
- 返すもの：
  - `q`：問題の文。答えの欄は `□`。`□` がなければ、最後に「＝ □」がつく。
  - `a`：答え（文字列）。単位や「あまり」をふくんでよい（例 `'6 cm 2 mm'`、`'7 あまり 3'`）。`□` が2つ以上あるときは、答えを順にならべた文にする（例 `'8時 15分'`）。
  - `easy`：楽な形（答えに［ ］で出る）。式なら「＝」でつないでよい。わなの問題は、楽にならないわけを（ ）で短く書く。
  - 必要なら `verify: () => true または まちがいの説明`（式で確かめられない問題の検算）。
  - 必要なら `easyCheck: false`：楽な形に途中の式（「7 × 8 ＝ 56」など）を書いて、答えとの検算をしないとき。
  - 説明の文（futsu・raku・mark・why・caution・easy）の □ は、書きこむ欄ではなく、ふつうの四角になる。
  - 必要なら `val`：楽な形（easy）の式がくらべる値（例：「□ ＋ □ ＝ 14」で答えが 7、楽な形が「7 ＋ 7」のときは `val: 14`）。ないときは答え、答えが式でなければ問題の式の値とくらべる。
  - 必要なら `also: ['1-20']`：この問題には、ほかのわざも使える（見わけようの答えに、使えるわざをすべて書く。M-4）。
- わざの定義に `fits(q, p)` を書くと、ほかのわざの問題でも、このわざが使えるか（q はルビをとった問題の文）を判定して、見わけようの答えに足す（なくてもよい）。

## 3. 文の書き方（第1巻）

- 教科書 第1巻と同じ、ひらがなの わかち書き（ことばの切れめに半角の空白）。例：`こたえが 10を こえる。`
- 漢字は、教科書 第1巻で使っている字だけにし、**かならずルビ**をつける：`《漢字|よ|み》`（1字ずつ読みを `|` で区切る。例 `《時間|じ|かん》`、`《九九|く|く》`）。ルビのない漢字は `check.js` がまちがいとして出す。
- 記号は全角の ＋ － ＝ と × ÷（教科書と同じ）。数字は半角。単位は半角（cm、mm、L、dL、mL、kg、g）。時・分は漢字でルビ（`《時|じ》`、`《分|ふん》`／`《分|ぷん》`）。
- 分数は `《f:1/4》`。
- 色だけで目印を示さない（M-7、K-15）。目印は `**…**`（中にルビがあってもよい。本では太字、アプリでは太字と下線）。

## 4. 確かめ（かならず）

1. `node mondai/build/check.js 1 1-26 1-27 …`（自分のわざの番号）：ぜんぶ OK になること。
   - 問題の数、答えと式の値、楽な形の値、ルビのない漢字、種を 200 とおり変えたときのまちがい、を見る。
2. `mondai/build/mk_pdf.sh 1`：本を組む（`tex/mq1.pdf`）。`mq_pages.py` の結果が `errors=0` で、NG の行がないこと。
   - NG「左ページがあふれた」が出たら、`futsu`・`raku`・`why`・`caution` を短くするか、`counts.s1` を減らす（左ページには目印〜ステップ1が入る）。
3. 組んだページを画像で見る（`pdftoppm -r 60 -f ページ -l ページ -png tex/mq1.pdf 画像のフォルダ/p`。画像は scratchpad に置く）。見開きの左右、字の重なり、答えの欄の大きさ。
4. `tex/mq1.*`（pdf・log・aux など）と、書き出した `tex/mq1-body.tex`・`-ans.tex`・`-list.tex` はコミットしない（事務局がまとめて書き出す）。

## 5. わざの中身の考え方

- ステップ1：目印がはっきり見え、すぐ楽な形にできる問題。
- ステップ2：1つ手を加えると目印が出る問題（入れかえる、たす順番を変える、など）。
- ステップ3：同じしくみが、ちがう姿で出る問題（大きな数、ことばの問題、□をもとめる問題など）。第1巻の少し先（★2）でもよい。
- わな：目印に似ているが、楽にならない・使えない問題。答えの楽な形には、そのわけを書く。
- 「どうして楽になるの？」は、どの決まり（10のまとまり、入れかえても同じ、分ける、など）から来るかを書く。教科書の章（1-2、1-13 など）を指してよい。
