## 決まったこと

1. **GitHub に移せる。** ソースは約950ファイル・圧縮して約37 MB で、GitHub の上限（1ファイル 100 MB、リポジトリは 1 GB 以下をすすめる）に十分収まる。非公開リポジトリの Actions のランナー（2コア・メモリ 8 GB）で、いちばん重い巻も組める（最大 約 5.3 GB）。
2. **リポジトリは非公開（Private）。** 名前の案は `butsuri-sugaku`。公開にするかは依頼者が決める。
3. **組版環境を固定してリポジトリに入れる。** Ubuntu 24.04 の TeX Live 2023 を apt で入れ（推奨パッケージは入れない）、Ubuntu にない LuaTeX-ja などは委員会が使ってきた版を `texmf/` に入れる。書体も `tex/fonts/` に入れる。版を上げるのは「全巻にかかる修正」として委員会で決める。
4. **正式な PDF は、Actions がまっさらな状態から組んだものとする。** 前に組んだときの記録が残っていると組み上がりが変わることがあると、移行の試験で分かったため（論点4）。
5. **組み方は委員会の手順と同じ。** `gen.py` → lualatex 2回 → もくじのページを照らす → ずれがあれば合わせて組み直す → カバー → ログの集計。エラー・もくじのずれ・PDF なしは Actions で失敗（赤）にする。はみ出し・未定義の参照は表に出す。目視と委員ごとの確認はこれまでどおり委員会が行う。
6. **Actions は「変わった巻だけ」組む。** 本文を直せばその巻、共通部品を直せば全巻。文書だけの変更・最初の push では組まない。手動の実行の既定はいちばん短いガイドブック。
7. **版はタグで渡す。** 作業用のブランチは `work/volN-verM`、渡すときのタグは `volN-verM`（ガイドブックは `guide-verM`）。タグを push すると、Actions が組んでリリースに PDF を添付する。版の番号はこれまでどおり渡した順に数える。
8. **リリースのファイル名**：GitHub はリリースのファイル名に日本語を使えないので、PDF は英数字の名前（`vol6_Ver2.pdf`）に納品の名前の表示名をつけ、あわせて中のファイルを納品の名前にした zip を添付する。
9. **委員会の手順との対応**：修正方針は `tools/FIX-*.md`（これまでどおり）、直しは作業用のブランチ、委員会の最終確認と議事録はプルリクエスト、依頼者の取りこみ（Merge）が「渡す」の合図。チャットでの納品も、依頼者が望むあいだは続ける。
10. **移し方は3通り**：Claude に任せる（おすすめ）、GitHub Desktop、ターミナル。ブラウザからのアップロードは使わない（1回100ファイルまでで、「.」で始まるフォルダが入りにくい）。
11. **ルビの記録の確かめを足す。** 移行の試験で、作業環境の `vol1.ltjruby`・`vol2.ltjruby` がこわれていたと分かった（論点4）。こわれた記録は消し、`build.sh`・`ci-build.sh` に確かめを足した。全巻にかかる修正事項 No.62 とした。

## 議論の記録

### 論点1　GitHub に移せるか

- **電気工学教授**：組版の結果が環境で変わらないことが第一です。TeX Live を「最新版」で入れると、LuaTeX-ja の版が変わって行の折り返しが変わる。今の環境とまったく同じ版を入れる形にしてください。
- **機械工学教授**：GitHub の非公開のランナーはメモリ 8 GB です。第9巻は以前 8 GB で止まったので、章ごとのごみ集めの仕組みを入れました。ほかの巻の最大メモリも計ってください。
- **数学教授**：数式の書体が1つ変わるだけで、全巻のページ送りが変わります。apt の「推奨パッケージ」で、意図しない書体が入らないかを確かめること。
- **校長**：無料枠に収まるかも大事です。毎回全巻を組むのでは足りなくなるでしょう。
- **結論**：決まったこと1・3・6。最大メモリは計測して仕様書 6章に載せた（論点4）。

### 論点2　何を正本とし、どう組むか

- **デザイナー**：PDF をリポジトリに入れると、版ごとに 5 MB ずつ増えていきます。PDF は入れず、組んだものを配る形に。
- **電気工学教授**：依頼者が受け取る PDF は、だれが組んでも同じであるべきです。「タグ＝渡した版」とし、タグから組んだ PDF をリリースに置きましょう。
- **小学校教師**：途中の PDF も見られるようにしてください。直しの確認はそこでします。
- **結論**：決まったこと4・7・8。途中の PDF は Artifacts（7日間）、確定した PDF はリリース。

### 論点3　委員会の進め方・版の番号・納品物

- **教育学教授**：これまで積み上げてきた「指摘の洗い出し → 委員の話し合い → 直す → 確認 → 議事録」は変えないこと。GitHub は道具で、手順の置きかえではありません。
- **校長**：プルリクエストを「委員会の最終確認」の場にし、議事録も同じプルリクエストに入れます。依頼者が Merge を押すことが「受け取った」の合図になります。
- **特別支援学校教諭**：手順書は、Git を使ったことのない人が迷わない順番と言葉で。ボタンの名前は画面のとおりに書き、表で一目で分かるように。
- **心理士**：うまくいかなかったときの手当てを先に書いておくと、安心して始められます。
- **YouTuber**：「入れただけで何時間も組み始める」のは怖いので、初回は手で、短いガイドブックから試せるようにしてほしい。
- **結論**：決まったこと6・7・9・10。手順書に「困ったときは」の表を置いた。

- **第1巻（17ページ）・第2巻（21ページ）のちがいの原因は2つあった。**
  1. **ルビの記録がこわれていた（1ページ）**：作業環境の `vol1.ltjruby`（ルビの位置の記録）が、10月22日に組版が途中で止まったときに途中で切れていた。LuaTeX-ja はこわれた記録を黙って使わない（ログに1行出るだけ）ため、Ver4 はルビの記録なしで組まれ、「形（直角）」のかっこのとなりのルビの位置が少しちがっていた。`vol2.ltjruby` も同じようにこわれていて、第2巻ではルビの位置のほか、1か所で行の折り返しが変わり、さくいんのページが1つ動いた（「表計算ソフト」387→386）。
  2. **Ver4 のあとに直した共通部品（16ページ）**：Ver4（10月22日）のあと、第3〜9巻とガイドブックを作るあいだに共通部品（`bk-b5.sty`・`bk-honbun.sty`・`bk-matter.sty` など）を直している。そのため今のソースで組むと、題名の2行目にルビがある章の初めのページで、章の帯と「道しるべ」の間が Ver4 より約 5 mm 狭くなる（ほかの章と同じ間になる）。こわれた記録を入れて組んでも、この16ページは変わらなかったので、原因は共通部品のほうである。
- **デザイナー**：今の組み方のほうが、題名の2行目にルビのない章（1-4 など）と帯の下の間がそろっていて、正しい形です。
- **校長**：第1・2巻（と、同じ10月22日に組んだ第5巻）を `main` から組むと、Ver4 のあとに直した共通部品が入ります。第3巻は Ver3 と全ページ一致しました。これは「全巻にかかる修正」の B 段階で入る予定のものなので、問題ありません。ただし依頼者には、`main` から組んだ第1・2巻（と第5巻）は、渡した版と少しちがうことをはっきり伝えましょう。
- **数学教授**：10月30日に渡した「第1〜5巻の組版 tex 一式」も、その時点の共通部品が入っているので、第1・2巻（と第5巻）は組むと渡した PDF と少しちがいます。これも伝えること。
- **結論**：決まったこと4・11。第1・2巻のこわれた記録は消した。仕様書 9章に結果と原因を載せた。

### 変えなかったこととその理由

- **TeX Live のインストールのキャッシュ（指摘28）**：推奨パッケージをやめてインストールが短くなったため。キャッシュは仕組みが複雑になり、版の固定を確かめにくくなる。
- **Mac で組む手順**：Mac の TeX は版がちがい、正式な PDF と同じにならないため、載せない。
- **GitHub の実際のランナーでの試験**：リポジトリができてから、手順書の手順3（ガイドブック）で確かめる。
